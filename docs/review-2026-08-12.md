# Bug-hunt and simplification review — 2026-08-12

Scope: `main` at `7aa3d9b`, reviewed on `review/bughunt-2026-08-12`.
The review concentrated on the seams introduced by Muse/ATEM, Granite, and
recent quant support. It intentionally excludes the documented
`tool_choice:"auto"` header-forcing loop, ATEM plan non-goals, performance
work, and new features.

## Ranked findings

### 1. High — buffered ATEM parsing read beyond its stated input length (fixed)

`tool_envelope_map` accepts a pointer and byte count, but the ATEM path used
`strstr`, which requires a trailing NUL. An exactly sized input buffer caused a
heap-buffer-over-read under AddressSanitizer. The parser now uses bounded
searches throughout the length-delimited path. A regression passes an
intentionally nonterminated buffer, and the focused suite is clean under
ASan/UBSan. Fixed in `88b167b`.

### 2. Medium — truncated numeric parameters could violate their schema (fixed)

An incomplete integer or number was recovered as `0` even when `minimum`,
`maximum`, or exclusive bounds rejected zero. Recovery now clamps its fallback
inside the compiled schema's declared interval. The regression covers an
integer constrained to `[5, 9]`. Fixed in `1a4a8ae`.

### 3. Medium — truncated string enums selected an unrelated member (fixed)

Any incomplete enum text was replaced by the first declaration. Recovery now
selects the member with the longest common prefix, preserving the model's
partial choice when possible; exact members remain unchanged. Fixed in
`45bead7`.

### 4. Low — skipped Muse history calls produced a leading turn separator (fixed)

The renderer used the source-array index to decide whether to insert the native
multi-call boundary. If an invalid entry was skipped before the first valid
entry, the output began with an orphan `<|eom|><|start|>` boundary. It now
counts emitted calls. Fixed in `91500aa`.

## Simplification leads

- **ATEM compiler wrapper family — applied.** Five overlapping public entry
  points were collapsed into one `schema_compile_atem_turn` function with an
  explicit start-mode enum and optional final schema. The parameterized private
  compiler remains the single implementation. Existing direct,
  after-reasoning, either-prefix, named, auto, structured-final, and parallel
  tests prove equivalent behavior. Commit `a7307fd`.
- **`max_items == 1` as whitespace metadata — concern refuted, cleanup
  applied.** A user enum cannot acquire an array/string bound through the
  current typed compiler, so the proposed degenerate JSON schema did not cause
  a live collision. The field reuse nevertheless obscured invariants and made
  a future collision plausible. A dedicated `whitespace_significant` node flag
  now carries protocol syntax metadata; `max_items` is only a real bound.
  Commit `fff37f9`.
- **Truncated enum and numeric fallbacks — applied.** See findings 2 and 3.
  Dropping a required key was rejected because it would turn a closable,
  executable call into a schema-invalid one. Bound-aware recovery is both
  deterministic and valid.
- **Parallel auto behavior — documentation applied.** README now states that
  native `parallel_tool_calls:true` plus `tool_choice:"auto"` retains the auto
  single-call turn; bounded two-call generation remains required/named only.
- **`pick_alt` indentation — applied.** The `SN_ARR` case is aligned with its
  sibling cases in `fff37f9`; no behavior changed.

## Reviewed with no additional fix

- Schema compilation and validation were run under ASan/UBSan and GCC's static
  analyzer after the flag/API reductions; no further memory or undefined
  behavior finding was produced.
- Template rendering and tool mapping were run under ASan/UBSan. After the
  length-bound fix, the focused template/tool binaries completed without leaks
  or memory findings.
- Recent Granite architecture routing and IQ quant dispatch were inspected at
  their model/quant integration boundaries. Their existing tolerance,
  compatibility, MoE, and real-model gates remained green; no minor isolated
  defect was found. Larger numerical or performance changes would be outside
  this review.
- The `tool_choice:"auto"` recipient-header forcing loop remains deliberately
  deferred: the certification addendum identifies it as design work, and this
  review was explicitly told not to alter it.
