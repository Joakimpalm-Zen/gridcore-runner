## Honest negatives

- Fixing gpt-oss token boundaries did **not** fix its conversation behavior.
  The five short raw greedy comparisons improved to 3/5 exact, but the chat
  smoke still runs to the token limit, hallucinates foreign `[/INST]` markers,
  and narrates its answer. That is a separate Harmony/template or generation
  problem, not evidence against the tokenizer fix.
- The ledger is deliberately incomplete where the manifest does not define an
  executable contract. In particular, CPU/CUDA, chat, tool, and long-context
  checks remain `not_executed` for many rows with machine-readable reasons.
  The report must not be read as 24 fully certified models.
- Two pinned files failed SHA verification. They were not silently treated as
  substitutes, and their model checks did not execute.
- The multi-part loader supports the standard numbered GGUF set and tensor
  mapping; it does not synthesize a merged file or accept an incomplete set.
- The first item-4 profiled opt-in run achieved only 59/60 layers because a
  foreign workload reduced the registry budget. It is retained as profiling
  evidence, not correctness evidence; the gate and production rerun both used
  full offload.
- One mandatory `make test` attempt saw 512.2 MB appear during the VRAM leak
  check and failed with its explicit concurrent-process diagnostic. No foreign
  process was killed. Complete reruns passed before every affected push.

## New findings, ranked

1. **High — Q4_0 prefill promotion coverage was a 54x performance boundary.**
   Kernel existence did not imply production use. Future CUDA quant kernels
   need a real-weight dispatch assertion and tolerance row as part of landing,
   or similarly large regressions can remain hidden behind an allowlist.
2. **Medium — compatibility declarations still underspecify executable
   contracts.** The new ledger makes this visible, but 23 CPU/CUDA and all 24
   chat rows were not executable from the current manifest. Adding structured
   parameters for these check classes is the next credibility improvement.
3. **Medium — gpt-oss chat failure is independent of its tokenizer.** Exact
   tokenization removes the former explanation and narrows follow-up to Harmony
   rendering/control-token handling or chat generation policy.
4. **Low — build artifacts need toolchain identity.** A reusable object name
   could mix native and cross/portable flags. The quant object is therefore
   rebuilt for every make invocation; a future object-based build should key
   its directory by target and flags instead.
